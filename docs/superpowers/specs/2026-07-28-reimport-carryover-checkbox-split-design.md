# 再取込時の引継ぎチェックボックス分割 設計書

日付: 2026-07-28

## 背景

同一工番へPDFを再取込する際、取込プレビュー画面には「追加工事契約金額・追加工事予算・今後の支出予定・備考欄」をまとめて前回データから引き継ぐかどうかを選ぶチェックボックスが1つだけ存在する(2026-07-11 12.3章で追加)。今回、この4項目をまとめて一括で引継ぐ/引継がないの二択ではなく、内容の性質が異なる2グループに分けて個別に制御したいという要望を受けた。

検討の結果、「契約金額が変わったかどうかで自動的に引継ぎ可否を判定する」という当初案は不採用とし、あくまで手動のチェックボックスを2つに分割するだけのシンプルな変更とすることで合意した。

## スコープ

- **対象**: 単体のPDF再取込フロー(取込プレビュー画面の「取り込む」ボタン、`#commitImportBtn`のクリックハンドラ)のみ
- **対象外**: フォルダ一括取込(`processFolderImport`)。現状通りチェックボックス無しで全項目を無条件に引き継ぐ仕様を維持する(一括処理は1件ごとの確認ダイアログを出さない設計のため、個別チェックボックスとは相性が悪いという判断)
- **対象外**: 契約金額の変更検知に基づく自動引継ぎ/自動クリアのロジック。今回は実装しない

## 変更内容

### 1. UI(`public/index.html`)

現在の単一チェックボックス行(`#reimportCarryOverRow`)を、独立した2つの行に分割する。表示順は以下の通り(今後の支出予定・備考欄を先に表示)。

- **チェックボックスA**「今後の支出予定・備考欄の内容を、この工番の既存データから引き継ぐ(項目コードが一致するもののみ)」
- **チェックボックスB**「追加工事契約金額・追加工事予算の内容を、この工番の既存データから引き継ぐ(項目コードが一致するもののみ)」

両方ともデフォルトでチェック済み(ON)。表示/非表示の条件は現行と同じ(`reimportTargetKoban`が設定されている、つまり再取込時のみ表示)。スタイルは既存の`.reimport-carry-over-row`クラス(および`[hidden]`companionルール)をそのまま再利用し、新規CSSは追加しない。

### 2. ロジック(`public/app.js`の`#commitImportBtn`ハンドラ)

現在の単一の`carryOver`フラグを、以下の2つの独立したフラグに置き換える。

- `carryOverForecast`(チェックボックスAに対応): 項目ごとの`yoteiShishutsu`(今後の支出予定)・`memo`(備考)を制御
- `carryOverBudget`(チェックボックスBに対応): プロジェクト直下の`tsuikaKoujiKeiyaku`(予定追加工事契約金額)、および項目ごとの`tsuikaKoji`(追加工事予算)を制御

前回工番データ(`previousItemState`)の読み込み自体は、再取込対象(`reimportTargetKoban`)が存在すればチェックボックスの状態に関わらず行う(値の適用箇所でどちらのフラグを見るかだけを分ける)。各フラグがOFFの場合、対応する項目は現行の「引継がない」場合と同じ初期値(今後の支出予定はPDFの値かゼロ、備考は空文字、追加工事予算はゼロ、予定追加工事契約金額はnull)にする。

新規取込(`reimportTargetKoban`が無い場合)は、両フラグとも常にfalse扱いで現行と変わらない。

### 3. 引継ぎ通知バナー(`#carriedOverNotice`)

プロジェクトの`carriedOverNotice`フィールドを、真偽値から「どちらのグループを引き継いだか」を表す情報(例: `{ forecast: boolean, budget: boolean }`)に変更する。バナー表示条件は「いずれか一方でも引継ぎが発生した場合」。表示文言は引き継いだ組み合わせに応じて出し分ける。

- 両方引継ぎ: 現行と同じ文言(4項目まとめて引き継いだ旨)
- 今後の支出予定・備考欄のみ: その旨の文言
- 追加工事契約金額・追加工事予算のみ: その旨の文言

**後方互換**: 本変更以前に保存された既存プロジェクトは`carriedOverNotice`が真偽値(`true`/`false`/未設定)のまま保存されている。読み込み時に`true`(レガシー形式)であれば「両方引き継いだ」相当として扱い、バナーの表示・文言決定ロジックが後方互換的に動作するようにする。

### 4. フォルダ一括取込(`processFolderImport`)への影響

挙動(常に全項目を無条件で引継ぐ)自体は変更しないが、上記3の通知バナーの新しいデータ形式に合わせて、`carriedOverNotice`の設定値を新形式(両方`true`)に更新する。これは表示の一貫性を保つための最小限の追随であり、機能変更ではない。

### 5. 操作説明書(`public/manual.html`)更新

「再取込時のデータ引き継ぎ」章(現在1つのチェックボックスを前提にした説明文・スクリーンショット)を、2チェックボックス仕様に合わせて更新する。

- 説明文を「2つのチェックボックスをそれぞれ個別にON/OFFできる」内容に書き換え
- 該当スクリーンショットを新UI(2チェックボックスが並んだ状態)で再撮影
- 既存のNode.jsスクリプトベースの安全な置換手法(13.2章の手法を踏襲、base64画像行をReadツールに読み込ませず`fs.readFileSync`/`fs.writeFileSync`で置換)を使用する

## 検証方針

Playwrightで以下を確認する。

- 再取込プレビュー画面に2つのチェックボックスが分離した順序(今後の支出予定・備考欄が先)で表示されること
- チェックボックスAのみON: 今後の支出予定・備考欄は前回値を引継ぎ、追加工事契約金額・追加工事予算はクリアされること
- チェックボックスBのみON: 逆のパターンが正しく動作すること
- 両方ON/両方OFFの組み合わせも含め、通知バナーの表示有無・文言が組み合わせごとに正しいこと
- 新規取込(再取込ではない場合)ではチェックボックス自体が表示されないこと
- 既存(分割前)のプロジェクトデータを開いた際、通知バナーの後方互換ロジックが例外なく動作すること
- フォルダ一括取込の既存の回帰(全項目無条件引継ぎ)が壊れていないこと
- manual.htmlの該当箇所が新UIと一致していること
